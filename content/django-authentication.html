Django Authentication

Today I explored Django's authentication system in depth. Django ships with a robust, batteries-included auth framework that handles user accounts, groups, permissions, and cookie-based sessions out of the box.

Session Authentication

Django uses session-based authentication by default. When a user logs in, the server creates a session and stores a session ID in a cookie. On subsequent requests, the browser sends this cookie, and Django uses it to look up the session and identify the user.

The flow works like this:

  1. User submits their credentials via a login form.
  2. Django's authenticate() function verifies the credentials against the database.
  3. If valid, login() creates a session and sets the session cookie.
  4. The AuthenticationMiddleware attaches request.user on every request.

Key Components

User Model

Django provides a default User model with fields like username, email, password, is_staff, and is_superuser. However, it's strongly recommended to create a custom user model at the start of a project:

from django.contrib.auth.models import AbstractUser

class CustomUser(AbstractUser):
    bio = models.TextField(blank=True)
    avatar = models.ImageField(upload_to='avatars/', blank=True)

Authentication Backends

Django supports multiple authentication backends. The default backend checks usernames and passwords against the database, but you can write custom backends to authenticate against LDAP, OAuth providers, or other systems.

Middleware Stack

Two key middleware classes make authentication work:

  • SessionMiddleware — manages sessions across requests
  • AuthenticationMiddleware — associates users with requests using sessions

Password Hashing

Django uses PBKDF2 by default with a SHA256 hash. Passwords are never stored in plaintext. The framework supports pluggable password hashers, including bcrypt and Argon2.

Always use make_password() and check_password() for manual password operations. Never roll your own hashing.

Decorators and Mixins

For protecting views:

  • @login_required — redirects unauthenticated users to a login page
  • @permission_required — checks if the user has a specific permission
  • LoginRequiredMixin — class-based view equivalent

Key Takeaways

  1. Always create a custom user model before running your first migration.
  2. Use Django's built-in views for login, logout, and password management.
  3. Never store passwords in plaintext — Django handles hashing automatically.
  4. Session authentication is stateful; for APIs, consider token-based auth (DRF).
